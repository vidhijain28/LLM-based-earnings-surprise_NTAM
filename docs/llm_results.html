0. Method: pipeline and prompts¶

Every run goes through the same four steps:

transcript ─► anonymize ─► summarize (optional) ─► score ─► regression
             company,      ~28x shorter,             ĝ in [0, 1]   PRank(r_abn) on ĝ and PRank(s)
             people,       fixed sections            + 3 reasons
             years masked
  1. Anonymize (llm_common.anonymize). Company name, ticker and speaker names are replaced with [COMPANY], [EXECUTIVE n] and [ANALYST n]. Four-digit years are replaced with [YEAR]. Financial figures stay in, since they are what the model has to judge.
  2. Summarize (llm_summarize). The transcript is cut to about 1/28 of its length, the paper's compression, in fixed sections: Results, Guidance, One-time items, Margins, Tone and caution, Q&A. Exact numbers are kept, each with what it is compared against. If the summary runs over the word limit, the model is asked once to shorten it.
  3. Score (llm_score). The model predicts where the call's one-day abnormal return will rank among all calls this quarter: 0 = worst, 0.5 = neutral, 1 = best. It answers in JSON with up to three reasons.
  4. Regress. The paper's specifications, in sections 3 to 8 below.

Prompt design choices worth knowing when reading the results:

  • The call, but no consensus. The model sees everything said on the call, numbers included: reported EPS, revenue, margins, guidance. It does not get the I/B/E/S consensus or the surprise (actual minus consensus) unless the run is labelled "+ EPS numbers". Management rarely says what analysts expected, so the model has to judge "better or worse than expected" from context: tone, guidance changes, analysts' questions.
  • "Relative to expectations" is in the prompt. The scorer is told that "strong results that were already expected are neutral, not positive". Section 7 shows the models stay optimistic anyway.
  • No outside knowledge. Both prompts tell the model to use only the text given. Anonymization makes it harder for the model to recognize the company.
  • No prompt optimization. The prompts were written once and not tuned on returns. The paper tunes its prompt with GEPA on the early half of the quarter (section 6).

  • s = PRank(SUE)

Every run uses the same y and s. If a call was scored twice, for example retried after a failure, the latest prediction is kept.

3. Main regressions, run by run (the paper's Tables 2-4)¶

The specifications follow the paper's tables:

  1. (1) Baseline: y = a + θ·s.
  2. (2) LLM alone: y = a + γ·ĝ.
  3. (3) LLM + surprise: y = a + γ·ĝ + θ·s.

Coefficients use conventional OLS standard errors in parentheses, as in the paper. R² comes with its 99% bootstrap interval in brackets: resample calls with replacement, refit, and take the 0.5th and 99.5th percentiles.

Within a run, every specification uses the same bootstrap draws. That makes the interval for ΔR² = R²(3) − R²(1) a paired one, the direct test of whether the LLM adds information beyond the surprise. The summary table comes first, then each run in full.

How big is an R² of about 0.1? Day-0 returns are mostly noise: market moves, industry news, order flow. The surprise alone, the standard earnings signal, explains about 5%. A text signal that adds 5 to 6 points is large in this setting, and it is the same size as in the paper.

4. Head to head on the same calls¶

Each run covers slightly different calls, so the runs are compared again on the calls every run scored, using one set of bootstrap draws. That gives:

  • a paired interval for each run's R² minus the first run's R², which says whether one model is really better;
  • the Spearman rank correlation between models' predictions: do they pick up the same information?

5. Side by side with the paper¶

The paper's numbers were typed in from its Tables 2-4 (N = 1,849). Each of our runs is placed next to the paper row with the same model and setup, where the paper has one. The paper reports intervals for each R², not for ΔR², so its ΔR² is the difference of two point estimates.

Differences to keep in mind:

  • Data: the paper uses Benzinga for the consensus and Massive for returns. We use I/B/E/S and CRSP, on more calls (US, Q4 2025).
  • Table 4: in the paper, every model scores Opus 4.5's summaries. Our "other model's summaries" runs use whichever model wrote them.

6. Early vs. late announcements (the paper's Table 5)¶

The paper splits the quarter at the median event date. The early half is its training set for prompt optimization, and the late half is held out. It finds the late half no harder. Our split is the same for every run: early means event_date <= median, with the median taken over all in-sample calls.

7. Calibration: does each model think every call is good news?¶

Events are sorted into quintiles of each run's prediction. Ties are broken at random with a fixed seed, because predictions take few distinct values. For each quintile the left chart plots the average prediction against the average realized return rank:

  • On the dotted diagonal, the prediction would be a calibrated rank.
  • A rising curve right of the diagonal means the model ranks well but is optimistic. That is the paper's "good is priced in" finding, which its GEPA optimization learned to correct. Our scoring prompt already says that expected good news is neutral (section 0), and the models are still optimistic. A sentence of instruction is not enough to correct this; tuning the prompt on returns may be.

The grey dashed line is the surprise rank, for reference. The right chart shows the day-0 abnormal return of the top quintile minus the bottom quintile. This is the announcement reaction itself, so it is not tradable.

8. Robustness¶

For each run:

  • Clustered standard errors: calls on the same event date share market and industry shocks, so t-stats are recomputed with standard errors clustered by event date.
  • Ranked prediction: PRank(ĝ) replaces ĝ. This removes each model's own scale and bias.
  • Transcript timing: the result is rerun on calls whose transcript was out by the event-day close.

9. Takeaways¶

The bullets below are generated from the results above, so they update when runs are added.

  • Baseline. The surprise alone explains R² = 0.047 [0.03, 0.07] of the return rank (paper: 0.050 [0.03, 0.08]).
  • Qwen3-30B-A3B · own summaries. LLM + surprise R² = 0.102 [0.08, 0.13]. The gain over the surprise is ΔR² = 0.055 [0.036, 0.079], clearly above 0. Closest paper setup: Table 3 (own summaries), where the paper's models get 0.073-0.130. Mean prediction 0.65 (bias +0.15). Early/late: 0.109 / 0.096.
  • Gemini 2.5 Flash-Lite · Qwen3-30B-A3B summaries. LLM + surprise R² = 0.110 [0.08, 0.14]. The gain over the surprise is ΔR² = 0.062 [0.041, 0.089], clearly above 0. The paper's Gemini 2.5 Flash-Lite in the same setup (Table 4) gets 0.112. Mean prediction 0.59 (bias +0.09). Early/late: 0.119 / 0.101.
  • Gemini 2.5 Flash-Lite · own summaries. LLM + surprise R² = 0.112 [0.09, 0.15]. The gain over the surprise is ΔR² = 0.065 [0.043, 0.093], clearly above 0. The paper's Gemini 2.5 Flash-Lite in the same setup (Table 3) gets 0.098. Mean prediction 0.60 (bias +0.10). Early/late: 0.117 / 0.110.
  • Head to head on 2,583 common calls: Gemini 2.5 Flash-Lite · own summaries 0.112, Gemini 2.5 Flash-Lite · Qwen3-30B-A3B summaries 0.110, Qwen3-30B-A3B · own summaries 0.102. The paired differences in section 4 show which gaps are real: a difference whose interval includes 0 is within noise.
  • Cost for 2,585 calls through OpenRouter: Gemini 2.5 Flash-Lite · Qwen3-30B-A3B summaries $0.25 (scoring $0.25, summaries —); Gemini 2.5 Flash-Lite · own summaries $4.98 (scoring $0.27, summaries $4.71). Local runs (Ollama, vLLM) show no cost.

Caveats (methodology differences from the paper):

  • What the model sees.
    • The paper says it feeds the model "the earnings numbers as well as the earnings call transcript" (p. 2).
    • Runs labelled "+ EPS numbers" get reported EPS, consensus and surprise (I/B/E/S) in the prompt. The other runs see only the text, so they can judge "vs. expectations" only from what management says.
    • A model that sees the surprise may partly copy it. Compare ΔR², not just R², across the two prompt variants.
  • Anonymization is incomplete. Section 2 shows, for each summarizer, how often years and company names survive. Years are masked in every transcript before summarizing, so years in a summary were written back in by the summarizer: it sees "fiscal [YEAR]" and fills in a guess. In a check of 150 summaries per model, no year survived masking. The filled-in year matched one in the original transcript 89% of the time for Qwen and 78% for Gemini; the rest were wrong guesses (often 2023 or 2024). Summaries are not masked again at scoring time, so the scoring model sees these years. Look-ahead risk stays low as long as every model was trained before October 2025.
  • Real time vs. after the fact. The paper scored calls live, as transcripts arrived. We scored after the quarter, which is fine for models trained before the sample.
  • Closest setup, not a replication. In the paper's Table 4 every model scores Opus 4.5's summaries. Ours score whichever model wrote the summaries, so those rows are comparable in design, not identical.
  • Data. I/B/E/S and CRSP here, Benzinga and Massive in the paper, with more calls here. The Qwen run was scored on an earlier pipeline build, so it covers slightly fewer of the current in-sample calls.
